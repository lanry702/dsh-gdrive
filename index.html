dsh-gdrive

Google Drive for DeepSeek Harness — an MCP server plus a small local plugin. personal project

DSH ships an MCP manager but no Drive connector. This plugin fills that gap: the model gets mcp__gdrive__search, mcp__gdrive__read and eight sibling tools, and can search, read, upload and organize files in the user's own Drive.

How it works

DSH Host
 └─ plugin @local/dsh-gdrive        resolves node, registers an MCP server
      └─ ctx.mcpManager.register('gdrive', { transport: 'stdio', … })
           └─ server.mjs                MCP stdio server, one JSON-RPC message per line
                └─ Google Drive v3 REST  with an OAuth refresh token kept on this machine

No SDK dependencies: OAuth (PKCE + loopback redirect) and the REST calls are hand-written, so the plugin keeps working across DSH upgrades.

Tools

ToolWhat it does
whoamiAuthorized account, grant level, storage usage
searchRaw Drive q= or friendly predicates (name / full text / mime / folder)
listFolder contents, folders first
readDocs→markdown, Sheets→CSV, Slides→text; binaries land in a local cache and the path is returned
downloadSave locally; native formats converted (Doc→docx, Sheet→xlsx, Slides→pptx)
uploadUpload a local file, optionally converting to a Google format
mkdir, moveCreate folders, move or rename entries
trashMove to trash, or restore from it
shareShare with a person, or with anyone holding the link

Authorization

Each user runs their own Google Cloud project and OAuth client — the plugin holds no shared credentials. A one-time auth command opens Google's consent screen, receives a refresh token over a loopback redirect, and stores it locally.

Data handling

Everything stays on the machine running the plugin. See the privacy policy for what is accessed, where it is stored, and how to revoke access.
